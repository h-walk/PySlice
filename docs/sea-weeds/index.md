# Into the SEA-weeds

Developer documentation: what exists in PySlice, why it exists, the invariants
that protect it, where its boundaries are, and how to extend it without
breaking the ecosystem contracts it participates in.

For using PySlice, start with the {doc}`../guides/getting_started` guide
instead.

## Developer overview

PySlice is a headless simulation library. It has no GUI, no CLI, and one
optional ecosystem coupling (sea-eco). The pipeline is linear:

```
Loader / build_slab / databases
        ↓
   Trajectory  ──(transforms: tile, orient, tilt, crop, frozen-phonon)──┐
        ↓                                                              │
   (optional) ORBMDCalculator / FAIRChemMDCalculator ────────────────────┘
        ↓
   MultisliceCalculator.setup(...).run()
        ↓
   WFData ──→ HAADFData
          └─→ TACAWData
```

Four layers, with a strict dependency direction — each depends only on those
above it:

| Layer | Modules | Owns |
|---|---|---|
| **Data / resolution** | `data/seashell.py`, `data/atomic_structure.py`, `data/pyslice_serial.py` | The sea-eco boundary, and only it |
| **Structure input** | `io/loader.py`, `io/build.py`, `io/databases.py` | Getting atoms in, and shaping them |
| **Simulation** | `multislice/*`, `md/*`, `backend.py` | The numerics |
| **Results** | `postprocessing/*` | Calibrated observables |
| **Agent surface** | `mcp/*`, `skills/`, `.claude/agents/` | Driving all of the above |

Peer pages, each covering one substantive feature:

- {doc}`resolution_layer` — how results become sea-eco objects implicitly, and
  the single-coupling-point rule.
- {doc}`signal_containers` — the `signal-containers` schema PySlice
  implements, and its conformance record.
- {doc}`structure_building` — exactly periodic slabs, and why carving is the
  fallback.
- {doc}`agentic_surface` — the MCP service, the planner, and how skills and
  subagents layer over them.

## Building the docs

Install the documentation dependencies, then build. Both commands below were
run to produce this page.

```bash
python -m pip install -r docs/requirements.txt
```

**API regeneration is mandatory before completing any documentation task**,
even when no diff is expected. PySlice's API Reference is generated by
`sphinx.ext.autodoc` at build time from the docstrings in `src/pyslice` —
there is no separate stub-generation step and no committed generated `.rst`,
so building the HTML *is* the regeneration:

```bash
python -m sphinx -b html docs docs/_build/html          # regenerates API Reference
python -m sphinx -b html -W docs docs/_build/html       # strict: warnings are errors
```

The strict build needs network egress: `intersphinx` fetches the Python,
NumPy, and ASE inventories, and Sphinx emits one warning per unreachable
inventory that no `suppress_warnings` subtype can silence — so `-W` fails on
an air-gapped machine for reasons unrelated to these pages. Drop the mappings
to verify strictness offline (cross-project links degrade to plain text):

```bash
PYSLICE_DOCS_OFFLINE=1 python -m sphinx -b html -W docs docs/_build/html
```

This is the command that verified the tree as committed; it reports
`build succeeded` with zero warnings.

Heavy optional dependencies (OVITO, torch, ORB, FAIRChem, the MCP SDK, h5py,
tqdm) are listed in `autodoc_mock_imports` in `docs/conf.py`, so the API
section builds without a GPU or the off-PyPI OVITO wheel.

PDF:

```bash
python -m sphinx -b latex docs docs/_build/latex && make -C docs/_build/latex
```

`latexmk` and a TeX distribution are required for the PDF target and are not
part of `docs/requirements.txt`; the HTML build is the gate used in practice.

Executable examples are checked by running them (see
{doc}`../guides/examples`); the ones needing `[md]`, a GPU, or OVITO cannot run
in a bare environment, and that limit is stated there rather than hidden.

**Output and artifact policy:** builds land in `docs/_build/`, which is *not*
tracked. Do not commit build output.

## Repository rules a change must preserve

1. **`data/seashell.py` is the only module that imports sea-eco.** Enforced by
   a source scan in `tests/32_seashell_resolution.py`, not by convention.
2. **Results are sea-eco objects when sea-eco is present, plain objects when
   it is absent** — and PySlice imports and simulates either way.
3. **Structure edits are `Trajectory` transforms**, returning new objects;
   never `setup()` arguments.
4. **The multislice grid reads only the box diagonal.** A non-diagonal
   `box_matrix` silently misdescribes the grid.
5. **`.sea` files and the packed cache formats are compatibility surfaces.**
   Prefer additive change; round-trip test anything that touches them.
6. **The parameter physics lives once**, in
   `skills/simulation-parameter-selection/SKILL.md`.
7. **No new dataclasses.** `Trajectory` predates the rule; do not copy the
   pattern.
8. **NumPy docstrings on every callable** — public, private, dunder, property.
   Documentation quality is part of code correctness.

## Testing

```bash
python -m pytest tests/27_mcp_service.py tests/28_databases.py \
  tests/29_slab_builder.py tests/30_plan_simulation.py \
  tests/31_sea_file_export.py tests/32_seashell_resolution.py \
  tests/18_cache_output_api.py tests/24_trajectory.py \
  tests/25_review_regressions.py tests/14_backend.py -q
```

Tests are numbered `NN_topic.py` and are **not** auto-discovered by a bare
`pytest` invocation — name them explicitly. GPU-, OVITO-, and
network-dependent tests gate themselves. `PYSLICE_DB_LIVE_TESTS=1` enables the
live COD round-trip.

**Known stale:** `tests/16_sea_eco_integration.py` imports names
`pyslice.data` no longer exports and cannot be collected. Live bridge coverage
is in `tests/31` and `tests/32`.
